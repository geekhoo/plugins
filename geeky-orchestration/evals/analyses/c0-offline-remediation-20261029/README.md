# C0 offline remediation

Five final real-Codex local-fixture configurations inside Windows MXC pass all
105 checks. The full scripted C0 mock completed five stages, passed 17 product
tests and 13/13 oracle tests stable over three repetitions. Every workload used
isolated state with network denied; native Responses requests went only to its
in-container loopback fixture. No paid model, upstream provider or live telemetry
was used. These results are scripted/model-free proof, not model-behavior proof.

## Fixed locally

- The native fixture now matches the classic-functions catalog actually used
  by the LiteLLM profile, rather than requesting unsupported custom tools.
- MCP discovery uses declared functions, waits boundedly during startup and
  requests tool search only after Codex advertises it. Router errors remain failures.
- File-write proof requires a fresh marker, exact bytes and successful command
  execution; an earlier attempt's file cannot satisfy the check.
- Codex implementation dispatch prescribes a cold, complete task brief. The
  canonical coder instructions distinguish worker identity from inherited
  orchestration history, disallow self-messaging/unowned waits, and describe a
  Windows PowerShell fallback. Five generated projections were synchronized.
- Offline counterexamples cover malformed search item IDs, unavailable tools,
  exhausted discovery, self-targeted calls and waits without an owned child.
- Profile-test exports exclude local .venv/test caches rather than copying them.
