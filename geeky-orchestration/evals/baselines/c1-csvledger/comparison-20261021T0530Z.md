## Why the runs differ

| Difference | Cause (evidence) |
|---|---|
| Task review: run 1 none, run 2 all 9 | Run 1 dispatched only coders during `geeky-implement`. The main-thread trace shows no `code-reviewer` until `impl-review`. Run 2 sent one reviewer per phase batch: "Review phases 1-2", "phase 3", "phase 4". The skill requires task review (EP:124–128); run 1 skipped it. |
| Gates: run 1 DoD + kanban, run 2 commit gate | Each run followed a different half of the same protocol. Run 1 ran `check-dod; validate-kanban` after each batch, but `check-commit` only once. Run 2 ran `check-commit` before most commits, but never `check-dod`. EP requires both (143, 177). |
| Commit grouping: per task vs per phase | EP:166 says "decide grouping by reading the diff yourself". Run 1 committed per task, then a tracking commit. Run 2 committed one `feat` per phase, so phases 3 and 4 bundled several concerns. |
| 7 vs 9 tasks | Different decompositions in `geeky-plan`. Not scored (D67). |
| impl-review NEEDS FIXES (run 2 only) | A design difference. Run 1's plan had `csvio.read_table(..., parse_row)` parse rows inline, so the first error wins. Run 2's plan validated every row's field count before the loaders parsed content. Run 2's spec named the risk ("Lazy decode order changes which error wins") but didn't make it a rule. |
| Run 2 used +3.3M tokens | 8 reviewer dispatches vs 4, 9 coders vs 7, subagent Reads 139 vs 81, plus a second impl-review round. |
| Run 2 has more LOC (414 vs 349) | Finer modules (`money`, `tabular`, `ledger`, `aggregate`) and a fix round. |
| Handoff and Run Summary | Run 1 kept a per-session handoff but no Run Summary. Run 2 wrote only a Run Summary, which names T1 and T9 but not T2–T8. |

### Environment problems affecting both runs (not agent behaviour)

1. **Every PowerShell tool call returns `Exit code 5`** inside MXC (39 of 39 in run 2), even when the command succeeds. On the host the same call returns a clean result. Plain `pwsh` in MXC exits 0. Setting `CLAUDE_CODE_TMPDIR` doesn't help. The cause is Claude's PowerShell-tool wrapper in the container and is still open. It marks every command as failed, which adds noise to V and to retries.
2. **pytest is missing from the sandbox's Python 3.13.** T1 coders spent their attempts installing it, and `pip` fails in the sandbox's temp folder. Run 1's T1 recorded 7 attempts with no pass. This depresses V for T1 and adds time and tokens.
3. **The seed repo has no git identity.** Agents committed as `Claude <noreply@anthropic.com>` via `git -c`.

Fix all three in the runner before further baselines. Otherwise environment noise stays mixed into the scores.
